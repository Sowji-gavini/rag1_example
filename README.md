# RAG Chatbot

A Streamlit web application that lets you upload a PDF and ask questions about its content using Retrieval-Augmented Generation. The app extracts text from the PDF, splits it into chunks, embeds them into a vector store, and uses Groq's language model to generate answers grounded in the retrieved context.


## Overview

This project implements a simple RAG pipeline entirely in Python. When a user uploads a PDF, the app processes it through a series of steps: text extraction, chunking, embedding, and vector indexing. At query time, the most relevant chunks are retrieved and passed to Groq's API along with the user's question to produce a context-aware answer.


## Features

- Upload any PDF file directly through the browser
- Extracts and chunks the full text of the document
- Generates embeddings using a sentence transformer model
- Stores and searches embeddings using a FAISS vector index
- Retrieves the top 4 most relevant chunks for each question
- Sends the question and retrieved context to Groq for answer generation
- Displays the generated answer along with the source chunks used


## Project Structure

    rag-chatbot/
    |
    |-- app.py
    |-- utils.py
    |-- requirements.txt
    |-- README.md

All core logic (PDF loading, chunking, embedding, vector store creation, retrieval, and Groq API call) lives in utils.py. The app.py file handles the Streamlit UI only.


## Functions in utils.py

load_pdf(uploaded_file) — extracts raw text from the uploaded PDF file

chunk_text(text) — splits the full text into smaller overlapping or fixed-size chunks

get_embedding_model() — loads and returns the sentence embedding model

create_vectorstore(chunks, model) — embeds all chunks and builds a FAISS index

retrieve_chunks(question, chunks, model, index, top_k) — embeds the question and retrieves the top_k most similar chunks

ask_groq(question, retrieved_chunks) — sends the question and context to Groq and returns the generated answer


## Installation

1. Clone the repository

        git clone https://github.com/your-username/rag-chatbot.git
        cd rag-chatbot

2. Create and activate a virtual environment (optional but recommended)

        python -m venv venv
        source venv/bin/activate        # On Windows: venv\Scripts\activate

3. Install dependencies

        pip install -r requirements.txt

4. Set your Groq API key as an environment variable

        export GROQ_API_KEY=your_groq_api_key_here      # On Windows: set GROQ_API_KEY=your_groq_api_key_here

5. Run the app

        streamlit run app.py


## Requirements

Add the following to your requirements.txt file:

    streamlit
    pypdf2
    sentence-transformers
    faiss-cpu
    groq

Adjust package names as needed depending on the specific libraries used in your utils.py implementation.


## How to Use

1. Launch the app using the command above
2. Upload a PDF file using the file uploader
3. Wait for the app to finish reading the PDF, creating chunks, loading the embedding model, and building the vector store
4. Type a question in the text input field
5. The app will retrieve the most relevant chunks from the document and display an answer generated by Groq
6. Expand the Retrieved Chunks section to see exactly which parts of the PDF were used to form the answer


## Pipeline Steps

Step 1 — PDF is uploaded and full text is extracted

Step 2 — Text is split into chunks for granular retrieval

Step 3 — A sentence embedding model is loaded

Step 4 — All chunks are embedded and stored in a FAISS vector index

Step 5 — User submits a question; it is embedded and compared against the index

Step 6 — Top 4 matching chunks are retrieved

Step 7 — Question and chunks are sent to Groq; the response is displayed


## Notes

- The Groq API key must be set before running the app; the app will throw an error if it is missing or invalid
- All processing happens fresh on each PDF upload; there is no persistent storage between sessions
- Error messages are displayed in the UI if any step in the pipeline fails
- The number of retrieved chunks (top_k) is set to 4 by default and can be adjusted in app.py
